# 한자 낚시터 설계 — v0.7 기출 유형 반복과 6급 합격 목표

**최신 요구 반영(2026-11-03): 학습을 통한 재미를 유지하고, 최종 목표는 한국어문회 6급 시험 합격입니다. 정규 진행에서 기출 유형 문제가 반복 출제되어야 합니다. 학습 진행의 다음 설계는18절을 우선하며 현재 로컬 구현은17절의 v0.6,19절의 원화·크기 개선,20절의 낚싯대·중앙 챔질 개선입니다. v0.7 출제 규칙이 게임에 적용됐다는 뜻은 아닙니다.**

구현 기록: 2026-10-26~27. 추가 설계 검토: 2026-10-29(15절), 2026-11-02(16절). 사용자 요청에 따라 **17절의 v0.6 첫 플레이 버전을 로컬에 구현**했습니다. 14~16절은 검토 당시의 제안이며 현재 적용 범위는17절을 기준으로 합니다. `hanja/`에 수채 배경·아이·물고기 자산과 누르고 놓는 챔질을 구현했습니다. 공식 300자 데이터와 6단계 읽기 낚시를 연결했습니다. 급수별 기억 연습·자체 연습시험·쓰기 윤곽 연습과 보호자 채점을 연결했습니다. 지역별 별도 풍경·협동·필순 전체 데이터·실제 시험 문항과의 난이도 대조는 후속 범위입니다. 아래의 초기 수치는 실제 아이 플레이 전 조정값입니다. 이전 문서는 `archive/hanja-fishing-design-v0.1.md`에 보존했습니다.

## 1. 제품 방향과 결정 상태

확정된 요구:
- 이름은 **한자 낚시터**입니다. 한자를 처음 배우는 두 초2 아이가 각자 패드에서 플레이하는 정적 웹/PWA 게임입니다.
- 한국어문회 **6급 시험 합격**을 최종 목표로 합니다. 읽기·뜻·낱말·관계·필순·급수별 쓰기를 함께 준비하며, 8급 앞에는 입문 구간을 둡니다.
- 학습에서 이해하고 기억해 문제를 풀고, 그 성취가 낚시 준비·수집·탐험으로 이어지는 재미를 유지합니다. 정규 진행에는 급수에 맞는 기출 유형 문제를 반복 출제합니다.
- 수채화 그림책 분위기를 유지하되, 한자와 조작 요소 주변의 배경 밀도를 낮춥니다.
- **낚시가 주 놀이**입니다. 객관식 문제마다 릴 연출을 붙이는 기존 흐름에서, 던지기·입질·챔질·힘겨루기·포획이 이어지는 흐름으로 바꿉니다.
- **누르고 있다가 떼는 순간** 타이밍을 판정하고 물고기의 힘을 줄입니다. 힘을 모두 빼면 포획합니다.
- 선택 단계는 **9급 / 8급 / 7-2급 / 7-1급 / 6-2급 / 6-1급**의 여섯 구간입니다.
- 6-2급부터 손가락 따라 쓰기를 제공합니다. 대결·순위·형제 비교는 넣지 않습니다.

초기 설계 제안 기록(현재 규칙은17절, 다음 설계는18절):
- 여섯 단계를 자유롭게 선택합니다. 순서대로 시작하도록 추천하되 아래 단계 완료를 강요하지 않습니다.
- 일반 물고기는 힘 100, 놓기 판정에 따라 50/35/20을 줄이는 값으로 손맛을 시험합니다.
- 첫 출조는 물고기 5마리 단위, 새 글자는 최대 3자, 배운 글자 재확인은 3마리마다 1문제로 시작합니다.
- 위 숫자는 구현·아이 관찰로 조정할 출발값이며 검증된 학습량이나 최적 난이도가 아닙니다.

## 2. 단계 이름과 한자 범위

게임의 단계명과 시험의 정식 이름을 분리합니다. 특히 **9급은 게임 내 입문 이름**이며 한국어문회 공식 9급으로 안내하지 않습니다. 카드에는 항상 `9급 · 입문`을 함께 적습니다. 7-1·6-1은 게임에서 단계를 구분하는 표기이며 시험 정식 이름으로 사용하지 않습니다.

- **9급 · 입문 — 마당 연못**
  - 공식 급수 대응: 없음. 8급 한자 중 쉬운 20자를 먼저 만나는 구간입니다.
  - 대상: 一 二 三 四 五 六 七 八 九 十 / 日 月 火 水 木 金 土 / 山 人 大.
  - 첫 조작 설명, 느린 게이지, 넓은 성공 구간. 현재 입문 20자 전체의 낚시와 학습 카드를 제공합니다.
- **8급 — 마을 개울**
  - 공식 대응: 8급. 누적 읽기 목표 50자, 입문과 겹치는 20자 외 새 글자 30자.
  - 입문 복습과 가족·방향·학교 등 기초 글자. 주제 배치는 배정표 대조 후 확정합니다.
- **7-2급 — 맑은 호수**
  - 공식 대응: 7급Ⅱ. 누적 읽기 목표 100자, 추가 50자.
  - 생활·몸·시간 등으로 묶되 실제 구성은 목록 검수 후 확정합니다.
- **7-1급 — 큰 강**
  - 공식 대응: 7급. 누적 읽기 목표 150자, 추가 50자.
  - 배운 글자의 한자어와 상대어를 확장합니다.
- **6-2급 — 바닷가**
  - 공식 대응: 6급Ⅱ. 누적 읽기 목표 225자, 추가 75자.
  - 먹물 쓰기 활동을 시작합니다. 읽기와 쓰기 대상 글자는 별도로 관리합니다.
- **6-1급 — 깊은 바다**
  - 공식 대응: 6급. 누적 읽기 목표 300자, 추가 75자.
  - 한자어·문장 맥락과 쓰기 복습을 확장합니다.

입문의 20자는 8급 50자에 포함되므로 합쳐서 70자로 세지 않습니다. 직접 8급에 입장한 아이에게도 50자 전체가 대상입니다. 이전 단계 학습 기록이 있으면 익숙한 글자로 활용하고, 없으면 새 글자로 소개합니다. 7급·6급 구간도 새 글자군과 해당 단계까지의 누적 복습 범위를 분리합니다.

**공식 배정표 수집 완료(2026-10-26)**: 한국어문회 공식 급수배정 페이지의 HWP 5개와 전체 XLS를 저장하고, 급수별 읽기·쓰기 목록을 대조했습니다. 300자와 단계별 누적 50/100/150/225/300자, 쓰기 50/150자가 일치합니다. 원본 훈음·부수·총획수·대체 훈음은 `hanja/data/catalog.json`에 저장했습니다. 상세 출처·검증은 `hanja/data/README.md`와 `validation-report.json`을 참조합니다. 글꼴·필순·음성·문항 구성의 검수는 별도이며, 자료 수집이 상위 단계 게임 구현 완료를 뜻하지 않습니다.

## 3. 단계 선택 화면

진입: 게임방 → **낚시 지도에서 단계 선택** → 출조 준비 → 연못.

- 가로 패드에서는 지역 그림과 단계명이 있는 카드 6개를 3열 2행으로 배치합니다. 작은 화면은 2열 또는 1열로 바꿉니다.
- 카드의 정보는 단계명, 장소 그림, 현재 선택 표시로 제한합니다. 긴 학습 설명과 세부 숫자는 선택 후 하단 정보 영역에만 보여줍니다.
- 초기 추천은 9급 입문, 다음 접속에서는 마지막으로 선택한 단계를 표시합니다. 추천과 플레이 가능 여부는 구분합니다.
- 하단 정보: `7-2급 · 맑은 호수 / 어문회 7급Ⅱ 기준 / 누적 읽기 목표 100자 / 새로 만날 글자·다시 볼 글자 / 이곳에서 낚시하기`.
- 완성된 콘텐츠는 처음부터 자유 선택할 수 있습니다. 제작 중인 단계는 `준비 중`으로 표시하고 실제 플레이 버튼을 제공하지 않습니다. 학습 잠금과 미구현 상태를 혼동시키지 않습니다.
- 직접 상위 단계에 들어가도 미학습 한자를 시험하듯 묻지 않습니다. 새 포획 글자는 소개하고, 재확인은 소개를 마친 글자에서만 냅니다.
- 단계 변경은 출조 경계나 쉬기에서 합니다. 이미 잡은 물고기와 확정한 학습 기록은 유지하고, 진행 중인 미포획 물고기는 지급하지 않습니다.

**단계와 손 조작 난이도는 분리합니다.** 6-1급 한자를 공부한다는 이유로 게이지가 빨라지거나 성공 구간이 좁아지지 않습니다. 출조 준비에는 `편안하게 / 기본`을 둘 수 있으며 첫 진입은 편안하게를 추천합니다. 이후 더 어려운 선택은 실제 요구가 확인될 때 검토합니다.

## 4. 한 마리의 낚시 — 상태와 입력

`물가 선택 → 던지기 → 입질 → 첫 당김(챔질) → 힘겨루기 → 포획 → 짧은 소개 또는 재확인 → 다음 낚시`.

1. **물가 선택·던지기**: 열려 있는 수면의 낚시 포인트를 탭합니다. 별도 거리·방향 게이지는 두지 않습니다. 선택한 위치에 찌와 물결이 나타납니다. 초기에는 같은 포인트 안의 위치별 효율 차이를 두지 않습니다.
2. **입질**: 찌의 움직임·소리·작은 안내가 함께 반응합니다. 반사신경을 시험하는 짧은 입력 제한은 두지 않습니다. 아이가 준비될 때까지 입질 상태를 유지합니다.
3. **누르기**: 큰 낚시 버튼을 누르면 게이지의 바늘이 왼쪽에서 오른쪽으로 움직입니다. 누르고 있는 동안에는 물고기의 힘이 줄지 않습니다.
4. **놓기**: 떼는 순간의 바늘 위치를 한 번 판정합니다. 첫 놓기는 챔질, 이후 놓기는 힘겨루기입니다. 별도의 복잡한 조작을 새로 가르치지 않습니다.
5. **반응**: 낚싯대 휨, 짧은 물보라, 효과음과 함께 힘 막대가 줄어듭니다. 글자 피드백은 `딱! / 좋아요 / 조금씩 당겼어요`로 구분합니다. 물고기를 때리는 장면이나 피해 숫자는 표시하지 않습니다.
6. **다음 당김·포획**: 힘이 남으면 바늘을 시작점으로 되돌리고 다음 누르기를 기다립니다. 연속 누르기를 강요하지 않습니다. 힘이 0 이하가 되면 즉시 포획으로 전환합니다.

초기 조정값:
- 일반 물고기 힘 100. 가운데 작은 임팩트 구간은 50, 넓은 성공 구간은 35, 나머지 구간은 20 감소.
- 따라서 일반 물고기 한 마리는 2~5번의 유효한 놓기로 잡습니다. 타이밍이 빨리 잡기와 반응 연출에 영향을 줍니다.
- 바늘 한 번 왕복 대신 우선 한 방향 이동으로 시험합니다. 약 2초에 한 번 끝까지 움직이고, 끝에서는 자동으로 놓기 처리하여 놓는 법을 몰라도 정지 상태에 갇히지 않게 합니다. 자동 판정은 임팩트 보너스를 주지 않습니다.
- 시작안은 넓은 성공 구간 40%, 그 안의 임팩트 구간 15%입니다. 첫 튜토리얼은 구간을 더 넓게 주거나 바늘이 구간에 닿을 때 `지금 놓아요`를 보여 줍니다. 실제 아이 조작에 따라 조정합니다.
- 전체 화면은 흔들지 않습니다. 한 번 당김의 반응은 짧게 끝내며 물고기마다 길게 반복되는 결과창은 띄우지 않습니다.

입력 예외:
- 손가락 한 개만 주 입력으로 잡고 포인터를 캡처합니다. 두 번째 손가락은 중복 당김을 만들지 않습니다.
- 포인터 취소·앱 숨김·쉬기에서는 당김을 취소하고 물고기 힘을 유지합니다. 시스템 취소를 유효한 놓기로 계산하지 않습니다.
- 버튼 밖에서 떼어도 주 포인터의 놓기를 한 번 처리합니다. 포획 직후 늦게 도착한 이벤트는 중복 기록을 만들지 않습니다.
- 키보드 스페이스·엔터도 누르기/놓기로 작동합니다. 손 조작이 어려우면 `자동으로 끌어올리기`로 같은 기본 포획과 학습 기회를 제공합니다.

## 5. 첫 연못의 재미와 난이도

첫 연못은 물고기 도주·낚싯줄 파손·미끼 소모·재화 손실을 넣지 않습니다. 구간 밖에서도 조금씩 진행하여 무한 실패를 방지합니다. 게임의 목표는 숙련된 사람이 더 빠르고 멋지게 잡는 데 두며, 느린 아이도 수집을 계속할 수 있게 합니다.

- 잘 맞추면 물고기의 짧은 도약과 반짝이는 물방울을 보여 줍니다. 이 보너스는 한자 정답률이나 숙련도에 더하지 않습니다.
- 일반 물고기는 짧게 잡고, 월척은 간헐적으로 등장시켜 특별하게 만듭니다. 월척의 힘·빈도는 아직 수치 확정하지 않습니다. 문제 5개를 연달아 푸는 기존 보스는 폐기합니다.
- 물고기 성격은 나중에 게이지 속도 **또는** 성공 구간 위치 중 하나만 바꿔 표현합니다. 처음에는 고정된 구간과 느린 바늘로 손맛부터 검증합니다.
- 물고기의 크기·무늬 수집과 어항 꾸미기, 지역마다 다른 풍경이 다시 낚을 이유입니다. 물고기 외형과 특정 한자를 고정 연결하지 않아 색만 보고 답을 고르는 것을 막습니다.
- 새 낚싯대·장비는 후속 검토합니다. 현 단계에서는 장비 구매나 능력치 상점으로 핵심 낚시를 복잡하게 만들지 않습니다.

## 6. 낚시와 한자 학습의 연결

**처음 잡은 글자**: 포획을 확정한 뒤 짧은 소개 카드를 보여 줍니다. 큰 한자·훈음·뜻 그림 또는 수량·쉬운 예시를 함께 제시하며 다시 듣기와 다시 보기 버튼을 제공합니다. 아이가 읽기 전에 자동으로 닫지 않습니다. 모르는 글자를 먼저 맞혀야 잡히는 구조는 사용하지 않습니다.

**이미 만난 글자**: 평소 포획은 작게 알리고 바로 다음 낚시로 이어집니다. 출조 중 3마리마다 한 번 배운 글자를 재확인합니다. 문제는 훈음→한자 / 한자→훈음 중 하나만 짧게 냅니다. 문제를 읽는 동안 낚시·게이지·진행 시간은 멈춥니다. 화면낭독·다시 듣기에서 정답을 읽어 주지 않습니다.

**처음 5마리 출조의 제안**:
- 처음 보는 글자는 최대 3자까지만 소개하고, 나머지는 이미 소개한 글자를 다른 물고기로 다시 만납니다.
- 3번째 포획 뒤 배운 글자 중 1문제를 재확인합니다. 이 빈도는 시험값이며 재미와 기억을 함께 관찰해 조정합니다.
- 5마리 뒤 작은 출조 마침 화면에서 `계속 낚기 / 내 어항 / 지도`를 선택합니다. 자동으로 다음 회차를 시작하지 않습니다.
- 높은 단계에 처음 들어간 경우에도 같은 방식으로 소량씩 새 글자를 소개합니다. 전 단계 전체 학습을 선행 조건으로 요구하지 않습니다.

오답 처리:
- 이미 잡은 물고기는 유지합니다. 틀린 선택과 목표 글자의 뜻·소리를 비교해 알려 주고, 두 번 어려워하면 함께 답을 봅니다.
- `함께 보기`로 학습 도움을 받을 수 있습니다. 보상·포획을 회수하지 않습니다.
- 첫 응답·도움 여부·문제 방향·최종 완료를 따로 저장합니다. 도움 후 완료는 독립 정답으로 세지 않습니다.
- 약한 글자는 다른 문제를 사이에 둔 이후나 다음 출조에서 다시 확인합니다. 즉시 같은 답을 눌렀다는 이유로 숙련 단계를 올리지 않습니다.

출조 횟수·수집 수·독립 정답은 다른 기록입니다. 낚시를 오래 했다는 이유만으로 한자를 익혔다고 표시하지 않습니다.

## 7. 화면 구성과 그래픽

수채 그림체는 유지합니다. 중앙 수면은 읽기·조작 공간으로 비우고 세밀한 풀·연꽃·바위는 가장자리에 둡니다. 아이와 부두는 작은 크기로 왼쪽 아래에 배치합니다. 제안 이미지 `art/hanja-fishing-graphic-proposal-v1.png`는 분위기 참고이며 배경 밀도와 게임 흐름을 그대로 확정한 화면이 아닙니다.

화면 상태별 정보:
- **평상시**: 지역명, 작은 수집 알림, 지도·도감·어항 메뉴. 상시 문제 배너와 큰 학습 사이드바는 없앱니다.
- **입질·힘겨루기**: 물고기 힘 막대 하나 + 하단 타이밍 게이지 하나 + 큰 낚시 버튼 + 쉬기. 힘 막대에 숫자는 표시하지 않습니다. 장력·릴 속도·거리 막대는 추가하지 않습니다.
- **포획**: 물고기가 올라오는 짧은 연출과 이름. 새 글자일 때만 소개 카드로 이어집니다.
- **재확인 문제**: 한자와 선택지 위주의 단순한 화면. 배경 움직임과 낚시 입력은 정지합니다.
- **내 어항**: 수집한 물고기와 꾸미기. 도감에서 훈음·낱말·필순을 다시 봅니다.

한자는 배경 그림과 분리해 한국식 자형을 확인한 글꼴로 똑바로 렌더링합니다. 물고기 움직임으로 글자를 반전·기울이거나 왜곡하지 않습니다. 글자 밑은 밝고 단순한 면으로 둡니다. 임팩트·성공 구간은 색뿐 아니라 테두리·표식·짧은 글로 구분합니다.

제작은 배경·아이·찌·낚싯대·물고기·UI 레이어를 분리합니다. 현재 canvas 그림은 프로토타입이며 정식 배경을 반드시 코드 그림만으로 제한하지 않습니다. 배경은 캐시하고 불필요한 매 프레임 재생성을 피합니다. 실제 패드 성능 확인 전 세밀한 수채 효과를 약속하지 않습니다.

## 8. 먹물 쓰기·복습·부모 기능

6-2급(어문회 6급Ⅱ 대응) 바닷가에서 문어 선생님의 먹물 쓰기를 시작합니다. 보고 배우기 → 따라 쓰기 → 혼자 쓰기의 순서입니다. 낚시 조작 중 쓰기를 겹치지 않고, 출조 사이 별도 활동으로 제공합니다. 월척 포획의 필수 조건으로 갑자기 쓰기 문제를 추가하지 않습니다.

- 읽기와 쓰기 기록을 분리합니다. 현재는 글자 윤곽을 따라 쓰고 보호자가 모양을 확인합니다. 방향·필순·필기 인식 자동 판정은 구현하지 않았습니다. 오류에 감점·물고기 회수는 없습니다.
- 쓰기 대상은 공식 쓰기 범위에 맞춰 이미 읽어 본 글자부터 시작합니다. 직접 6-2급에 입장해 모르는 글자는 뜻과 소리를 먼저 소개합니다.
- 한국식 필순·자형, 공개 획 데이터의 라이선스, 쓰기 범위는 공식 자료와 검수 후 투입합니다. 종이 연습장 인쇄를 부모 화면에 둡니다.
- 복습은 글자·방향별 첫 응답·도움 여부·최근 확인 시점을 사용합니다. 하루 복습을 추천할 수 있지만 접속 연속 보상이나 순위로 압박하지 않습니다.
- 물고기의 크기·희귀 무늬는 수집 요소입니다. 학습 숙련도와 같은 뜻으로 표시하지 않습니다. 어항 물고기를 오답으로 작게 만들거나 빼앗지 않습니다.
- 부모 화면은 약한 글자·방향별 기록·학습 시간·시간 제한을 제공합니다. 모의 시험은 낚시와 분리하며 공식 유형·문항 수·합격선을 확인한 뒤 만듭니다.
- 각자 패드 저장부터 시작합니다. 협동 축제·선물·기기 공유는 후속 기능이며 대결은 없습니다.

## 9. 저장과 구현 상태 모델

설계 필드 예시이며 기존 저장 형식을 즉시 변경하지 않습니다.
- 단계: `stageId`(intro9, grade8, grade7_2, grade7_1, grade6_2, grade6_1), `displayLabel`, `officialGrade`, `contentReady`, `newCharacters`, `cumulativeCharacters`.
- 콘텐츠의 공식 급수와 출조 단계를 분리합니다. 입문에서 만난 一을 8급에서도 동일한 글자로 인식하고 기록을 공유합니다.
- 출조: 단계, 조작 난이도, 현재 포획 수, 이번 새 글자 수, 소개 완료한 글자, 다음 재확인 시점.
- 물고기: 글자 ID, 외형 ID, 힘, 포획 상태, 포획 보상 지급 여부. 외형의 희귀도와 학습 정답은 분리합니다.
- 조작: idle / cast / bite / holding / pullFeedback / caught / learning / paused. 학습·쉬기에서는 낚시 타이머를 중단합니다.
- 기록: 포획 횟수와 양방향 응답 이력을 별도로 저장합니다. 중복 이벤트는 포획·응답을 두 번 반영하지 않습니다.
- 쉬면 확정한 포획과 응답을 저장합니다. 진행 중 물고기를 재개할지는 후속 판단이며, 초기에는 미포획 물고기 지급 없이 안전하게 종료합니다. 저장 실패는 사실대로 안내합니다.
- 이전 숫자 시안의 수집 기록은 유지합니다. 기존 `caught`·`independent` 누적만으로 새 숙련도나 다음 복습 시점을 만들어 내지 않습니다.

## 10. 구현 순서와 검증 기준

1. 한자 문제 없이 일반 물고기 한 마리의 던지기→입질→누르기/놓기→힘 감소→포획 손맛을 만듭니다.
2. 힘 100과 50/35/20 판정, 느린 바늘·넓은 구간, 자동 끌어올리기·쉬기를 적용합니다.
3. 여섯 단계 선택 화면을 붙입니다. 준비된 단계만 플레이되게 하고 이름·공식 대응·누적 범위를 표시합니다.
4. 입문 숫자 10자에 새 포획 소개와 3마리마다 재확인을 연결합니다. 처음부터 모든 급수 콘텐츠가 완성된 것처럼 표시하지 않습니다.
5. 도감·어항 저장과 출조 마침을 연결한 뒤 두 아이의 실제 반응을 관찰합니다.

검증 기준:
- 누르고 있는 동안 힘이 줄지 않고 놓을 때만 한 번 줄어드는가. 최선 2번·일반 3번·모든 약한 판정 5번으로 포획되는가.
- 시스템 취소·두 번째 손가락·연타·쉬기·포획 후 늦은 입력이 중복 포획을 만들지 않는가.
- 상위 단계 직행, 미구현 단계, 입문/8급의 같은 글자 기록이 올바르게 처리되는가.
- 처음 보는 글자를 묻지 않는가. 포획 유지·도움 기록·읽는 동안 정지·음성 답 노출 방지가 되는가.
- 실제 아이가 설명 없이 다시 던지는지, 릴을 번거로워하는지, 도움 없이 놓기를 익히는지 관찰합니다. 오래 플레이했다는 사실과 한자 기억을 따로 봅니다.
- 다음 날 글자 색·물고기 외형을 바꿔 뜻과 소리를 다시 확인합니다. 두 아이의 결과를 전체 연령의 검증으로 일반화하지 않습니다.

v0.3 구현에서 위 1~4의 흐름을 연결했습니다. 한자 관련 테스트 21개와 기존 영어·수학 테스트 43개가 통과했습니다. 브라우저에서 챔질 힘 100→50, 5마리 출조, 도움받음 복습, 상위 단계 직행, 데이터 로드 실패 시 메뉴 비활성화, 다른 페이지를 다녀온 뒤 복구를 확인했습니다. 768×1024와 390×844 크기에서 배치를 점검했습니다. 실제 아이·물리 패드의 손 조작·TTS 청취·저장 실패 주입은 아직 검증하지 않았습니다. 기존 검토 문서 끝에 v0.3 재검토 기록을 추가했습니다.

## 13. 급수 합격을 향한 학습 구현 v0.4 (2026-10-26)

제품의 끝 목표는 수집 수가 아니라 선택한 급수의 시험 준비입니다. 연못 아래 `급수 도전` 입구 하나를 두고 `만나기 → 기억하기 → 급수 도전 → 약한 부분 재학습 → 재도전`으로 이어집니다. 낚시는 계속 독립적으로 놀 수 있고, 5마리 출조 마침에서도 도전 지도로 이동할 수 있습니다.

- **만나기**: 낚시의 새 글자 소개와 학습 카드 중 하나로 학습 범위를 늘립니다. 카드로 배웠다고 포획·어항 수를 늘리지 않습니다.
- **기억하기**: 배운 글자와 그 글자들로 구성된 낱말·선택지만 사용해 최대 10문제를 냅니다. 최근 오답을 우선하며 독음·훈음을 직접 입력합니다. 힌트는 문항별로 저장되어 나가기·새로고침 후에도 독립 정답으로 바뀌지 않습니다. 풀이 후 바로 다음 글자를 골라 주지 않고 재학습으로 이어집니다.
- **급수 도전**: 급수의 누적 범위에서 자체 제작 문항으로 출제합니다. 미학습 글자도 나올 수 있음을 시작 전에 알립니다. 힌트·정답 공개는 제출 후에만 제공합니다. 문항은 한 번 제출하며 미응답을 분모에서 빼지 않습니다. 시간은 절대 마감 시각으로 저장해 새로고침으로 늘어나지 않습니다.
- **결과**: 유형별 점수, 미응답, 풀이, 쓰기 채점 대기를 제공합니다. 목표 점수에 도달하면 다음 급수를 선택하는 길을 열되 다른 단계 선택을 잠그지 않습니다. 오답은 카드 또는 해당 글자의 쓰기 재연습으로 연결합니다. `뜻·음 직접 확인`은 같은 글자에 독음·훈음을 각각 직접 맞힌 기록이며 숙달 선언은 아닙니다.
- **쓰기**: 6-2급 50자, 6-1급 150자. 옅은 글자 윤곽 따라쓰기 후 기준 글자를 숨겨 혼자 씁니다. 선택 상자도 훈음만 표시합니다. 시험은 처음부터 정답 없는 빈칸입니다. 손글씨 초안·제출 답안을 저장하고, 빈 답은 정답 처리하지 않습니다. 선이 있다는 이유로 자동 정답 처리하지 않습니다. 보호자가 모양을 확인하기 전에는 최종 연습시험 통과 판정을 내리지 않습니다. 따라쓰기의 보호자 확인 성공은 독립 점수와 구분합니다.

## 14. 장비·찌·물고기 다양화 검토 (2026-10-26, 제안)

현재 상태: 물고기 그림은 `fish.webp` 한 장에 색조만 5단계로 바꿉니다(`hue-rotate`). 재화·상점·장비는 없고, 물고기 힘은 모두 100입니다. 5절의 원칙(도주·줄 파손·미끼 소모·재화 손실 없음, 확률 보상 없음, 한자 난이도와 손 조작 난이도 분리)을 지키는 방향으로 검토했습니다.

### 14-1. 재화: 조개껍데기 🐚

- 포획 1마리 = 🐚1, 복습 문제를 **혼자** 맞히면 🐚+2, 기억 연습 완료 🐚+3처럼 **고정값**으로 줍니다. 뽑기·무작위 상자는 넣지 않습니다.
- 도움받은 정답도 포획 보상은 같게 줍니다. 혼자 맞힌 보너스만 다릅니다.
- 낚시 시간만으로 벌 수 있는 양에 상한을 둡니다(예: 하루 낚시 보상 🐚30). 그래야 낚시만 하고 학습은 건너뛰는 흐름을 막을 수 있습니다.
- 두 아이의 가격과 보상은 똑같습니다. 잔액은 서로 비교해서 보여 주지 않습니다.

### 14-2. 낚싯대 구매

낚싯대는 **손맛과 갈 수 있는 곳**을 바꾸고, 한자 정답에는 영향을 주지 않습니다.

| 낚싯대 | 얻는 법 | 효과 |
|---|---|---|
| 대나무 낚싯대 | 기본 | 일반 물고기 |
| 버들 낚싯대 | 🐚 구매 | 성공 구간 조금 넓게(편하게 잡기) |
| 단단한 참나무 낚싯대 | 🐚 구매 | 월척(힘 150~200)에 도전 가능 |
| 은빛 릴 낚싯대 | 🐚 구매 + 7급 지역 도착 | 한 번 당길 때 힘이 조금 더 줄어듦, 강·바다 전설 물고기 도전 |
| 바다 낚싯대 | 🐚 구매 + 6급Ⅱ 지역 도착 | 바다 전설 물고기, 특별한 던지기 연출 |

- 낚싯대마다 효과는 **한 가지씩만** 둡니다. 효과가 너무 세면 놓는 순간을 맞히는 재미가 사라지므로 상승폭을 작게 잡습니다.
- 낚싯대가 없어도 기본 포획과 학습 진행은 막지 않습니다. 월척·전설 물고기 도전만 열어 줍니다.

### 14-3. 내구도: 실제로 닳아서 부러지는 방식 (2026-10-26 사용자 요청으로 검토)

처음 제안한 "손질 게이지"는 보류하고, 실제로 닳아서 부러지는 방식을 검토합니다. 이 방식의 걱정거리는 세 가지입니다. 손이 느린 아이가 손해를 보는 것, 잡던 물고기를 잃는 것, 형제 사이의 다툼입니다. 아래 규칙으로 이 셋을 막습니다.

**무엇이 닳나**
- **산 낚싯대만 닳습니다.** 기본 대나무 낚싯대는 절대 부러지지 않습니다. 언제든 다시 낚시할 수 있어서 낚시를 못 하게 되는 일이 없습니다. 입문(마당 연못)은 대나무 낚싯대만으로 충분하게 만들어, 5절의 "첫 연못은 손실 없음" 원칙도 지킵니다.
- **당긴 횟수가 아니라 잡은 마리 수로 닳습니다.** 일반 물고기 1, 월척 3, 전설 물고기 5. 놓는 타이밍이 서툴러 여러 번 당겨도 더 닳지 않습니다. 이렇게 해야 손이 느린 아이가 손해를 보지 않습니다.

| 낚싯대 | 가격(🐚) | 내구도 | 고치는 값(🐚) |
|---|---|---|---|
| 버들 낚싯대 | 30 | 40 | 12 |
| 참나무 낚싯대 | 60 | 50 | 20 |
| 은빛 릴 낚싯대 | 100 | 60 | 35 |
| 바다 낚싯대 | 150 | 70 | 50 |

- 수치는 출발값입니다. 기준은 **"낚싯대 하나를 쓰는 동안 번 조개가 고치는 값보다 늘 많다"**입니다. 일반 물고기 40마리면 최소 🐚40을 버니 고치는 값 12를 내고도 남습니다. 낚싯대 때문에 조개가 줄어들기만 하는 구조는 만들지 않습니다.

**언제, 어떻게 부러지나**
- **물고기와 힘겨루기 중에는 절대 부러지지 않습니다.** 내구도가 0이 되는 물고기도 끝까지 잡히고, 도감에도 오릅니다. 잡은 뒤 물가에서 "뚝!" 하고 부러지는 장면이 나옵니다. 물고기를 놓치는 일은 없습니다.
- 복습 문제·쓰기 중에는 부러지는 장면이 나오지 않습니다. 출조 중간이면 다음 물고기는 자동으로 대나무 낚싯대로 이어집니다.
- **미리 알려 줍니다.** 30% 남으면 낚싯대에 금이 가는 그림, 10% 남으면 "조금만 더 쓰면 부러질 것 같아요"와 남은 마리 수를 보여 줍니다. 갑자기 부러지지 않게 합니다.
- 부러지는 장면은 짧고 귀엽게 만듭니다. 슬픈 음악·큰 소리·화면 흔들림은 쓰지 않고, 바로 아래 선택지를 보여 줍니다.

**부러진 뒤**
- 부러진 낚싯대는 사라지지 않고 **창고에 "부러진 낚싯대"로 남습니다.** 그 낚싯대로 잡은 마리 수도 기록에 남습니다.
- 고치는 방법은 두 가지이고 아이가 고릅니다.
  1. **조개로 고치기**: 표의 고치는 값을 내면 바로 새것처럼 됩니다(새로 사는 값의 약 1/3).
  2. **공방에서 고치기**: 배운 한자 문제 10개를 풀면 무료로 고쳐집니다. 혼자 맞힌 문제만 셉니다. 도움받은 문제는 세지 않지만 틀려도 벌은 없습니다. 쓰기 단계(6급Ⅱ~)에서는 먹물 쓰기 1자를 문제 3개로 칩니다.
- 조개가 모자라도 공방으로 언제든 고칠 수 있습니다. 그래서 "돈이 없어서 영영 못 쓰는" 상황은 생기지 않습니다.
- 조개 잔액은 0 아래로 내려가지 않고, 빚이나 자동 차감도 없습니다.

**미리 손보기 (선택)**
- 부러지기 전에도 공방에서 문제 5개를 풀면 내구도를 절반 채울 수 있습니다. 부러지기를 기다리지 않고 미리 손보는 습관이 자연스럽게 복습으로 이어집니다.
- 최대 내구도는 줄어들지 않습니다(고칠수록 약해지는 규칙 없음).

**두 아이 사이**
- 가격·내구도·고치는 값은 두 아이가 똑같습니다. 상대의 낚싯대 상태나 조개 잔액은 보여 주지 않습니다.
- 협동 기능이 생기면 **"고쳐 주기 선물"**을 둘 수 있습니다. 내가 공방에서 푼 문제로 형제의 부러진 낚싯대를 고쳐 주는 방식입니다. 부러짐이 다툼이 아니라 도와주는 계기가 되게 합니다.

**부모님 화면**
- 아이가 부러짐을 너무 속상해하면 **"낚싯대 닳기 끄기"**를 켤 수 있게 합니다. 끄면 낚싯대가 닳지 않고 다른 규칙은 그대로입니다.

**아이들과 확인할 것**
- 부러졌을 때 속상해서 그만두는지, 고치러 공방에 가는지 지켜봅니다.
- 공방이 귀찮은 숙제처럼 느껴지는지, 조개로만 고치는지 봅니다. 조개로만 고친다면 하루 조개 상한과 고치는 값을 조정합니다.
- 두 아이 중 한 명만 자주 부러뜨리는지 봅니다. 그렇다면 내구도를 늘립니다.

### 14-4. 찌: 무엇을 낚을지 고르는 도구

찌를 꾸미기만 하는 대신, **어떤 물고기가 물지를 아이가 고르는 장치**로 씁니다.

- 🔴 **빨간 찌 — 새 물고기**: 아직 만나지 않은 한자가 뭅니다(한 출조에 새 글자 최대 3자 규칙 유지).
- 🔵 **파란 찌 — 아는 물고기**: 이미 만난 한자, 특히 다시 볼 때가 된 한자가 뭅니다.
- 🟡 **금빛 찌 — 그림자 물고기**: 약한 한자가 있을 때만 쓸 수 있습니다(14-6절).
- 모양·무늬(오리, 연꽃, 별 모양 등)는 🐚로 사는 꾸미기 요소로만 둡니다. 효과는 색으로만 정합니다.

| 깊은 바다 | 도미, 복어, 가오리, 고등어 |

- 종류마다 크기 3단계(작은·보통·큰)와 색 변형을 둡니다. 그림은 지금처럼 수채 이미지로 생성하고, 몸통 가운데를 비워 한자를 덧씁니다. 대략 24종 × 크기 = 그림 24장으로 시작할 수 있습니다.
- 크기는 **릴 보너스**(그날의 손맛)로 정하고, 한자 숙련도는 물고기 옆의 표식(처음 만남 / 다시 보기 / 혼자 맞힘)으로 따로 보여 줍니다(검토 P1-4).

**부수 무늬 (자동 장식)**
- 한자의 부수에 따라 물고기에 무늬를 덧입힙니다. 예: 水부(13자) → 물결 무늬 지느러미, 木부(14자) → 잎사귀 꼬리, 火부 → 불꽃 꼬리, 日부 → 해 무늬 비늘, 口부 → 동그란 점, 言부 → 말풍선 거품, 艸부 → 풀잎 등지느러미, 心부 → 하트 볼.
- 상위 부수 12~16종이면 300자의 상당수를 덮습니다. 그림 12~16장만 추가하면 됩니다.
- 무늬가 같은 물고기들끼리 부수가 같다는 것을 자연스럽게 익히게 됩니다. 도감에 "같은 무늬 물고기 모으기"를 두면 부수 공부로 이어집니다.

**구현 상태 (2026-10-27, 1단계 완료)**
- `hanja/js/fish-kinds.js`: 지역별 3종씩 18종(금붕어·송사리·붕어 / 피라미·버들치·쉬리 / 잉어·메기·납자루 / 쏘가리·꺽지·은어 / 망둥어·볼락·놀래기 / 도미·복어·고등어)을 SVG 수채화로 그립니다. 그림 파일 없이 종류별 몸 모양·꼬리·색·무늬 값으로 만들고, 수채 번짐·종이 결은 SVG 필터 하나를 함께 씁니다. 가재·꽃게·가오리는 몸 모양이 달라 이번엔 뺐습니다.
- 부수 무늬 16가족(물결·나무·풀잎·불꽃·해·달·리본·말방울·하트·조약돌·번개·발자국·창문·보석·바느질·줄)이 300자 중 213자를 덮습니다. 나머지 87자는 무늬 없이 그립니다. 무늬는 꼬리·등·입 앞에만 그려 가운데 한자를 가리지 않습니다.
- 낚을 때마다 지금 지역의 3종 중 하나가 나오고, 잡은 종류를 기록(`collection[id].kind`)해서 어항에 그대로 보여 줍니다. 예전 기록은 글자가 처음 나오는 지역에서 고정으로 고릅니다.
- 새 한자 소개 카드에 "물결 무늬 금붕어 · ‘水’ 부수 친구들과 같은 무늬예요"를 보여 줍니다. 복습 문제는 지금처럼 무늬 없는 글자 카드로 냅니다.
- 테스트 `tests/hanja-fish-kinds.test.cjs` 5개. 크기 3단계와 "같은 무늬 모으기" 도감은 아직입니다. 나중에 AI 수채 그림으로 바꾸려면 `svg()`만 이미지로 바꾸면 됩니다.

### 14-6. 어려운 한자의 유니크 물고기

"어려운 한자"를 두 종류로 나눠서 다르게 대접합니다.

**A. 원래 어려운 한자 → 전설 물고기 (지역마다 5자, 총 약 30자)**
- 고르는 기준: 획이 많은 글자(體 23획, 讀 22획, 藥·禮·醫·題 18획 등), 소리가 여럿인 글자(車·金·樂·北·行·畫 등 11자), 뜻이 추상적인 글자.
- 각자 **뜻을 담은 고유 그림과 이름**을 줍니다. 예: 電 → 번개 뱀장어, 風 → 바람 날치, 雪 → 눈꽃 은어, 花 → 꽃잎 잉어, 樂 → 노래하는 복어(소리가 셋이라 셋으로 부풀기). 그림이 뜻을 떠올리게 해 주는 기억 도우미가 됩니다.
- 힘이 150~200이라 여러 번 당겨야 하고, 특별한 연출과 도감의 금테 칸이 있습니다. 놓는 정확도 요구는 일반 물고기와 같습니다(한자 난이도 ≠ 손 조작 난이도).
- 그 지역의 글자를 어느 정도 만난 뒤(예: 지역 글자의 절반)에만 나타납니다. 뽑기처럼 무작위로 나오지 않고, 조건을 채우면 다음 출조의 마지막 물고기로 **확정 등장**합니다.

**B. 이 아이에게 어려운 한자 → 그림자 물고기**
- 복습에서 두 번 이상 틀리거나 도움을 받은 글자는 어항에서 **그림자 물고기**(회색 실루엣)로 바뀝니다. 벌이 아니라 "아직 이름을 다 모르는 물고기"라는 느낌으로 보여 줍니다.
- 금빛 찌로 그림자 물고기를 낚아, 다른 날 **혼자 두 번** 맞히면 그 글자만의 **반짝이 물고기**로 변신합니다. 변신 장면과 도감 기록이 보상입니다.
- 어떤 글자가 반짝이가 되는지는 아이마다 다릅니다. 그래서 두 아이의 어항이 저마다 달라지고, 비교 대신 서로 구경하는 재미가 됩니다.
- 학습 원칙: 문제를 낼 때는 한자를 무늬 없는 카드에 씁니다. 물고기 모양이 뜻을 알려 주는 단서가 되지 않게 하려는 것입니다.

### 14-7. 제안 구현 순서

1. 지역별 물고기 종류 + 부수 무늬 (규칙 위험이 없고 바로 재미가 커짐)
2. 빨간·파란 찌 선택
3. 조개 재화 + 낚싯대 2~3종 상점
4. 그림자 물고기 → 반짝이 변신
5. 전설 물고기 (지역별 5자, 그림 30장)
6. 낚싯대 내구도·부러짐·공방 수리 (상점과 월척이 생긴 뒤)

결정이 필요한 것: 조개 하루 상한, 전설 물고기 30자 목록, 낚싯대 가격·내구도 출발값. 내구도 방식은 실제로 닳아서 부러지는 방식으로 검토 중입니다(14-3절).

## 15. 배송 상점·손맛·그래픽 통합 검토 v0.5 (2026-10-29, 미구현 제안)

사용자 요청: 한 글자씩 배우는 낚시는 유지하고, 높은 급수의 빠른 챔질과 하/중/상 임팩트, 크기별 체력과 줄 끊김, 문제의 정답 물고기를 제출하는 판매·코인 흐름, 두 번 실패 후 문제 교체, 기출 데이터 및 그래픽 품질을 검토합니다. 이번 작업은 설계와 검토용 화면입니다. 게임 코드·저장 형식·공개 사이트에는 적용하지 않았습니다. 아래 제안은 14절의 장비·내구도·그림자 물고기안과 충돌할 때 우선하는 다음 구현 후보입니다.

### 15-1. 판단과 우선순위

좋은 변화는 낚시 뒤에 ‘누구에게 어떤 한자를 보내는가’라는 목적이 생긴다는 점입니다. 게임의 반복은 `낚고 소개받기 → 배운 한자 배송 → 코인과 꾸미기 → 짧은 직접 회상·쓰기 → 급수 연습시험 → 다음 출조`로 연결합니다. 포획·판매·한자 선택 성공·직접 회상·쓰기는 각각의 기록입니다. 판매 정답률이나 플레이 시간만으로 시험 준비 완료를 선언하지 않습니다.

- **채택:** 하/중/상, 크기별 체력, 문제에 맞는 실제 어획 제출, 두 번 실패 후 해설과 교체.
- **조정:** 급수별 속도 상승은 ‘도전 권장값’으로 둡니다. 높은 급수에서도 편안 모드를 고를 수 있습니다. 글자 난이도와 손 조작 능력이 같다고 가정하지 않습니다.
- **조정:** 당긴 총횟수 대신 회복 가능한 줄 장력을 씁니다. 처음 만난 글자·기본 낚시는 보호하고, 도전에서만 파손을 허용합니다. 시간제 도주·장비 내구도·유료 수리를 동시에 넣지 않습니다.
- **판매 완충:** ‘문제를 맞혀서 판매’가 기본 동선입니다. 어려우면 ‘함께 제출’로 기본 가격에 팔 수 있어야 합니다. 첫 독립 정답 보너스와 도움 기록은 분리합니다. 모든 보상을 혼자 맞힌 답에만 묶지 않습니다.
- **권리 확인:** 기출 원문을 앱에 넣는 일과 공식 유형에 맞춘 자체 문항 제작은 별도입니다. 원문 탑재는 이용 허락 범위를 확인한 자료부터 합니다.

낚시 도전과 코인 경제를 같이 강화하면 어느 변화가 흥미나 회상에 영향을 줬는지 알기 어렵습니다. 기반과 판매 동선을 먼저 적용하고, 체력·속도·장력을 순차적으로 검증합니다.

### 15-2. 먼저 고칠 현재의 효율 역전

현재 `fishing-engine.js`는 체력100, 상50/중35/하20이며 `game.js`의 놓기 피드백은650ms입니다. 즉시 놓기5회의 피드백 합계는 약3.25초입니다. 편안 모드에서 중앙까지1.4초 누르는 상2회는 약4.10초입니다. 입질·포획 소개·사용자의 대기를 제외한 계산이므로 실제 총 포획 시간은 아닙니다. 그럼에도 즉시 놓기 연타가 정확한 타이밍보다 효율적일 수 있다는 결함은 있습니다.

다음 구현에서는 **당김 회차당 판정은 한 번**, 다음 회차 시작은 같은 시점으로 고정합니다. 일찍 놓아도 즉시 다음 유효 당김을 시작하지 못합니다. 놓는 순간에는 결과·물보라를 바로 보여주고, 남은 회차는 물고기의 저항과 줄을 늦추는 행동으로 채웁니다. 단순 대기처럼 느껴지는지는 실기기에서 확인해야 합니다. 바늘 속도·입질 대기·결과 효과의 시간은 서로 다른 값으로 관리합니다.

### 15-3. 손맛 초깃값과 줄 상태

모든 수치는 검증 전 출발값입니다.

- 편안 모드: 전 급수 편도2,800ms, 기본 포획 보호. 자동 끌어올리기는 계속 무료입니다.
- 도전 권장값: 입문2,800 / 8급2,700 / 7-2급2,600 / 7-1급2,500 / 6-2급2,400 / 6-1급2,300ms. 사용자가 느리게 바꿀 수 있습니다.
- 상 구간은 중앙15%, 상을 포함한 중 이상 구간은40%로 고정합니다. 속도를 올리면서 구간까지 좁히지 않습니다.
- 표시: 하 ‘살살’ / 중 ‘좋아요’ / 상 ‘딱!’. 모두 체력을 줄이며, 상만 잡히는 구조는 피합니다.
- 크기별 체력: 소형60 / 중형90 / 대형120 HP. 체력은 크기만으로 정하고 급수·희귀도 배율을 곱하지 않습니다.
- 상/중/하 감소량:50/35/25 HP. 같은 등급만 반복하면 소형은2/2/3회, 중형2/3/4회, 대형3/4/5회입니다. `ceil(체력/감소량)`이며 파손과 휴식은 제외한 수치입니다.

도전의 줄 장력은0~100점입니다. 상+10 / 중+18 / 하+25점, 줄 늦추기1초에−40점, 60점에서 경고, 100점에서 파손을 시험합니다. 계속 당기기보다 잠깐 늦추는 행동이 의미를 갖습니다. 대형에 하3회 후 늦추기1회를 넣으면 장력75→35→60→85점으로 포획할 수 있습니다. 상을 못 맞혀도 완주할 수 있습니다.

- 체력0과 장력100이 같은 판정에서 성립하면 **포획 우선**으로 정의합니다. `caught`와 `escaped`는 동시에 발생하지 않습니다.
- 파손 시 이번 미포획 물고기만 도주합니다. 이전 재고·도감·학습 기록·코인·낚싯대는 보존합니다. 기본 장비로 즉시 재시작하고 수리비나 독립 정답10개를 강요하지 않습니다.
- 첫 출조·새 한자 첫 만남은 파손 보호를 둡니다. 도전에서 놓친 미소개 글자를 배운 것으로 자동 기록하지 않습니다.
- 쉬기·앱 숨김·전화·포인터 취소는 장력 상승이나 파손을 만들지 않습니다. 복귀 시 재시작 정책을 명시하고 중복 포획하지 않습니다.
- UI에는 체력 막대와 타이밍 트랙을 유지합니다. 장력은 줄 곡률·연결점 표식·‘느슨/적당/팽팽’과 짧은 문구로 알리되, 경고를 충분히 인지하지 못하면 접을 수 있는 작은 표시를 검토합니다. 색만으로 위험을 알리지 않습니다.

현재 기하 함수의 `tension`은 누른 시간의 진행값을 이용한 시각 변수입니다. 실제로 누적·회복되는 줄 장력과 구분해 새 상태를 정의해야 합니다.

### 15-4. 배송 상점 — 문제와 재고를 함께 검증

1. **주문 생성:** 목표 급수, 글자뿐 아니라 낱말·독음의 소개 여부, 재고, 답의 허용 집합과 수량을 확인합니다. 답이 존재하는 주문만 냅니다. 후보가 적으면 안내형 주문/함께 제출을 제공하며 가짜 학습 점수를 만들지 않습니다. 선택지가1개뿐인 배송은 독립 선택 보너스 대상이 아닙니다. 보기는 주문별로 순서를 바꾸고 정답의 위치를 고정하지 않습니다.
2. **화면:** 주문 하나 → 보유 어획4~6개씩 → 선택한 개체 → 제출. 대상 정답의 예약 상태·훈음·강조색을 미리 보여주지 않습니다. 모든 재고를 한 번에 작은 글자로 펼치지 않습니다.
3. **첫 오답:** 물고기를 소모하지 않습니다. 무엇이 다른지 짧게 설명하고 선택을 해제해 다시 고르게 합니다. 중복 클릭이 자동 두 번째 오답이 되지 않게 합니다. 첫 응답은 이미 기록되므로 뒤의 성공을 독립 정답으로 바꾸지 않습니다.
4. **두 번째 오답:** 정답과 풀이를 함께 확인하고 다른 주문으로 교체합니다. 재고·코인은 그대로이며 오답은 복습에 남습니다. 같은 거래의 보너스 자격은 교체로 복구되지 않습니다. 의도적으로 계속 틀려 첫 정답 보너스를 회복하는 통로를 막습니다.
5. **정답:** 요구한 실제 개체만 소모하고 기본 가격과 해당 보너스를 지급합니다. 완료 영수증에서 제출을 잠그고 ‘다음 주문’의 별도 동작으로 새 거래를 엽니다. 연속 클릭이 다음 거래까지 확정하지 않게 합니다. 같은 글자 물고기가 여러 마리면 조건에 맞는 어느 개체든 제출할 수 있습니다. 낱말 주문은 순서·반복 글자별 수량까지 확인합니다.
6. **도움:** 도움은 정답·뜻·음을 안내한 뒤 아이가 해당 물고기를 직접 선택·제출하게 하고 기본 가격을 지급합니다. 도움 버튼만으로 자동 판매하지 않습니다. 독립 정답 보너스는 없지만 포획 가치가 깎이지 않습니다. 선택 연습·도움 후 완료라는 기록으로 남깁니다.

경제 예시는 소/중/대 기본4/6/8코인, 첫 독립 정답+2코인입니다. 첫 오답 이후·도움 후 성공은 기본 가격만 지급합니다. 이는 잠정안이며 시간당 수입과 크기 편중을 관찰한 뒤 조정합니다. 기본 장비·기본 수리·읽기300자·쓰기50/150자·단계 선택은 계속 무료입니다. 코인은 우선 낚싯대 외형·찌·어항 꾸미기에 씁니다. 하루 수입 상한이나 수리비로 공부를 강제하는 규칙은 초기안에 넣지 않습니다.

검토 중 의견 차이: 경제 담당은 도움 정답도 같은 보상, 학습 담당은 기본 대금과 독립 보너스 분리를 권했습니다. 여기서는 기본 대금을 보장하고 작은 첫 독립 보너스를 더하는 안을 채택하되, 도움이 필요한 아이가 현저히 적게 꾸미지 못하는지 확인합니다. 경쟁·형제 잔액 비교는 하지 않습니다.

**문제 예시는 자체 제작이며 공식 기출이 아닙니다.** ‘나무 목’에 맞는木를 배송하는 활동은 뜻·음→한자 선택 연습입니다. 木를 보고 뜻과 소리를 직접 쓰는 시험의 훈음 문항과 같은 수행으로 집계하지 않습니다. 반의·상대어·낱말 완성은 선택 배송에 잘 맞지만, 독음·훈음·뜻풀이·동음이의어는 실제 응답 형식으로도 따로 확인합니다. 필순·직접 쓰기는 물고기 선택으로 대체하지 않습니다. 쓰기 채점 대기 때문에 기본 배송대금이 묶이지 않도록 쓰기 활동은 별도 학습으로 둡니다.

**반례**
- 다른 적합한 주문이 없는 경우 같은 문제를 ‘다른 문제’라며 반복하지 않습니다. 안내 학습/함께 제출로 전환해 기본 판매를 마칠 수 있습니다.
- 카드로水를 배웠지만 잡지 않았다면 학습 문제는 풀 수 있어도 배송은 불가능합니다. `learned`와 실제 재고는 다른 전제입니다.
- 소리가‘수’인 물고기 주문에는水·手가 모두 맞을 수 있습니다. 허용 답 집합을 두거나 뜻·문맥으로 문제를 좁힙니다.
- 六·月을 소개했다고六月의 독음‘유월’까지 가르친 것은 아닙니다. 글자·낱말·문맥 독음의 소개 기록을 구분합니다.
- 문항의 `ids`에는 지문/상대 글자도 들어 있습니다. 이를 차감할 물고기 ID로 바로 쓰지 말고 `requiredAnswerUnits`를 따로 둡니다.
- 판권이 있는 원문을 단어 몇 개 바꿔 배송 문항으로 만든 뒤 자체 제작이라 표시하지 않습니다. 자체 문항과 허락받은 변형은 출처를 구분합니다.

### 15-5. 저장·거래·기존 기록 이관

현재 `collection[id].caught`는 누적 포획 기록이고 `kind`는 마지막으로 잡은 어종입니다. 개별 어획의 크기와 판매 여부가 아닙니다.

- 영구 도감/학습 기록: 기존 한자 ID, 누적 만남·포획·소개·답변 이력. 팔거나 놓쳐도 지우지 않습니다.
- 판매 재고: `fishUid`, `characterId`, `speciesId`, `sizeClass`, `caughtAt`, `priceRuleVersion`, `reservationOrderId`, `status`를 가진 실제 어획입니다. 상태는 `available/reserved/sold/display-only` 등으로 구분하고 장식용 도감 복제본은 판매할 수 없습니다.
- 주문: `orderId`, `transactionId`, 문항/유형/변형 출처, `acceptedAnswerUnits`, `requiredAnswerUnits`의 수량, 예약 개체, 최초 응답·도움·실패 횟수·보너스 자격, 생성 시점의 재고 버전을 둡니다.
- 거래: 정답과 최신 재고·예약·권리 상태를 다시 검사하고 재고 차감·코인·장부를 한 저장 단위로 확정합니다. 이미 확정한 거래 ID 재실행은 기존 결과를 반환합니다. 두 탭 동시 판매에는 저장 잠금/단일 활성 거래와 재고 버전 검사를 적용하고 실제 경쟁 조건을 시험해야 합니다. 클라우드 동기화 시에는 서버 거래가 필요합니다.
- 저장 실패·새로고침·탭 종료에서도 재고만 빠지거나 코인만 늘지 않게 합니다. 복구할 수 없는 중간 상태는 판매 UI에 남기지 않습니다.
- 과거 포획에는 크기와 개체 이력이 없습니다. 수량은 보존하되 대표 어종을 개별 포획의 실제 기록으로 꾸미지 않습니다. 기존 포획 묶음 재고로 이관하고 공통 기본 가격을 적용하는 후보를 검토합니다. 많은 누적 수를 한 번에 개체 배열로 펼치지 않습니다. 크기·희귀도 수집 성취를 소급 생성하지 않습니다.

### 15-6. 기출 수집·데이터화 계획

2026-10-29 한국어문회 [공식 기출문제 페이지](https://www.hanja.re.kr/kccpt/exam/previousQuestion.do)를 직접 읽어113·114회 자료와 목표5급수(8·7Ⅱ·7·6Ⅱ·6)의 다운로드 항목10개를 확인했습니다. 안내에는 한국어문회의 저작권/소유권과 허가하지 않은 온라인 배포 등을 금지한다는 내용이 있습니다. 이 확인으로 원문 사용 허락을 얻은 것은 아닙니다.

로컬의 무시 경로 `docs/sources/hanja-official/2026-10-29/`에 세션 값을 제거한 안내 페이지, SHA-256, 회차·급수·파일 항목 메타데이터를 저장했습니다. 원문 문제 파일은 미다운로드이며 OCR·문항별 전사·데이터화·공개를 수행하지 않았습니다. 파일 형식·정답 동봉 여부도 미검사입니다. 사용자는 설계를 요청했으므로 기관에 연락하거나 자료 이용 승인을 요청하는 메시지도 보내지 않았습니다.

실행 순서:
- 제공처·회차·급수·원본 URL·파일명/해시·원문 문항 위치와 권리 상태를 등록합니다. 게임 표시/변형/온라인 배포/오프라인 캐시 각각의 허용 범위를 확인합니다.
- 허용 범위가 확인된 자료는 원문 보관 → 텍스트 추출/OCR → 문항·공유 지문·밑줄·도형·정답 영역 분할 → 배정 한자와 매핑 → 사람이 원문·정답을 대조합니다.
- `sourceType`은 자체 제작/허락받은 기출/허락받은 변형으로 구분합니다. `rightsStatus` 미확인/비허용 자료가 공개 번들·서비스 워커 캐시에 들어오면 배포 검증을 실패시킵니다.

- 한국식 자형과 호환 한자 원문을 보존하고 조회 키만 정규화합니다. 다음자 뜻·음의 짝, 문맥 속 두음/속음, 필순 그림, 낱말 순서·수량을 확인합니다. 총획수만으로 필순을 생성하지 않습니다.
- ‘배송에 쓰기 적합’, ‘직접 회상으로 확인’, ‘그림/필기 필요’를 구분합니다. 자체 훈음·독음·낱말·필순 문항을 먼저 늘려 개발을 진행할 수 있으므로 기출 이용 허락이 전체 개발의 선행 차단 조건은 아닙니다.

현재 자체 콘텐츠의 낱말78개·완성형3표현·유의어2쌍·동음어3쌍·필순二/三/十만으로 전체 시험 대응을 선언하지 않습니다. 동음이의어의 선택지 독음만 달라 뜻을 몰라도 푸는 현재 문제도 문항 목표와 맞는지 재검수 대상입니다.

### 15-7. 그래픽·효과의 품질 방향

18종과 부수16가족은 이미 구현되어 있습니다. 공통 `bodyPath`, 지느러미 구조, 노이즈 시드, 이동 주기가 반복되는 것이 체감 단조로움의 근거입니다. 수채 번짐·종이 결 필터는 이미 있으므로 ‘SVG라서 수채가 아니다’라고 단정하지 않습니다. 종마다 다른 해부 구조·붓질·안료·움직임이 필요합니다.

1. 대표 원화5종(금붕어·송사리·메기·도미·복어)을 우선 제작합니다. 색 없이도 구별되는 머리/몸통/꼬리자루/수염을 만들고 기존18종으로 확장합니다.
2. 몸통·꼬리·가슴지느러미·입 연결점을 분리합니다. 유영·저항·포획·회복을 종별로 다르게 움직이며 어종별 입 앵커를 줄 기하와 공유합니다. 한자는 생성 이미지에 넣지 않고 독립된 검수 글꼴로 표시합니다.
3. 크기3단계는 실제 크기/체력/가격과 연결하되 한자까지 축소하지 않습니다. 문제 보기의 최종 한자36px 이상을 시작 기준으로 검증합니다. 좁은 체형은 별도 이름표를 써서 글자와 무늬를 겹치지 않게 합니다.
4. UI는 종이 패널·낚싯대/찌·동전·아이콘의 선 두께·재질·모서리·눌림 상태를 통일합니다. 현재8px 안내 등 작은 글자부터 정리해 핵심 안내14px·보조12px·터치48px을 초기 기준으로 확인합니다.
5. 하/중/상 효과는 색 외에 파문 크기·표식·문구·소리로 구분하고 약150/250/400ms의 짧은 국소 효과부터 시험합니다. 전체 화면 흔들림·긴 결과창은 추가하지 않습니다. 필기 중에는 유영과 입자를 모두 멈춥니다.
6. 질감은 사전 합성·캐시하고 동시 물고기3/어항6/입자24/DPR2를 초기 예산으로 검증합니다. 숫자는 현재 측정 성능이 아닙니다. 320×568·375×667·768×1024에서 가림/넘침을 확인하고, 저사양 패드10분 동안 프레임 시간p95 33ms 이하·필기 반응p95 50ms 이하를 목표로 측정합니다.

기존14절의 ‘틀리면 어항 물고기가 회색 그림자로 변함’은 오답이 수집의 상실처럼 보일 수 있습니다. 이번안에서는 잡은 외형을 보존하고 복습할 편지/주문 표시로 다시 만날 이유를 제안합니다. 배운 기록과 물고기의 아름다움을 감점하지 않습니다. 의미를 알려주는 전설/부수 무늬는 학습 도우미이며, 시험형 독립 확인에서는 해당 단서를 가립니다.

### 15-8. 구현 순서·검증·검토 범위

- 1차: 당김 회차·취소·중복 판정, 개체 재고와 영구 도감, 거래의 단일 확정을 먼저 만듭니다.
- 2차: 보유·소개·정답 집합/수량에 맞춘 배송 주문, 두 실패 뒤 교체, 함께 제출과 기본 대금, 오답 복습과 직접 회상을 연결합니다.
- 3차: 대표5종 원화·관절·접점 효과와 작은UI 품질을 높입니다.
- 4차: 크기별 체력을 검증한 뒤 도전 속도와 회복 가능한 줄 장력을 하나씩 적용합니다.
- 5차: 권리와 원문/정답 검수를 통과한 문제를 확대하고 필순·직접 쓰기·급수별 실제 응답 유형을 강화합니다.

구현 전에 반드시 막을 오류는 정답 재고 부족, 복수 정답 오채점, 도감 삭제, 중복 코인, 저장 중 재고 유실, 도움 정답의 독립 점수화, 줄 파손과 포획의 동시 지급입니다. 재미/학습 관찰과 별개인 정확성 조건입니다.

아이별로 자발적 다음 출조, 파손/판매 실패 직후 중단, 과도한 도움, 낚시와 문항에 쓴 시간, 다음 날 무늬 없는 한자에서의 직접 정답과 종이에 쓰기를 확인합니다. 1일/3일/7일 복습과 한 출조 새 글자0~3자는 시험할 시작안이지 확립된 최적 학습법이 아닙니다. 두 아이의 관찰을 전체 아동의 학습 효과 증거로 일반화하지 않습니다.

독립 검토: Dalton(손맛/경제), Hilbert(학습/문항), Epicurus(물고기/UI)가 코드를 읽고 의견을 냈습니다. 검토는 정적 분석과 기존 이미지 확인이며 새 실기기 측정은 아닙니다. 최종 규칙은 의견을 통합한 주담당 제안입니다. 비교 화면 `docs/hanja-fishing-next-design.html`과 별도 Canvas는 예시 상태만 바꾸며 실제 게임 저장을 건드리지 않습니다.

## 16. 학습 준비와 실제 어종 낚시의 분리 v0.6 (2026-11-02, 방향 검토)

사용자 의견: 현재 게임성이 약하고, 실제 물고기 도감을 보여주면 좋겠습니다. ‘물고기 한 마리 = 한자 한 글자’ 대신 ‘한자 공부·문제 → 아이템 수집 → 낚시’로 바꿀지 검토합니다. 이번 결과는 **변경을 권하는 설계 후보**입니다. 사용자 확정·구현·공개 배포나 아동 대상 검증을 뜻하지 않습니다. 앞선 15절의 한자 물고기 판매 퀴즈는 비교를 위한 이전안으로 남기며, 새 방향에서 동시에 적용하지 않습니다.

### 16-1. 판단: 연결은 풀고, 놀이 안의 선택을 만듭니다

1:1 연결을 푸는 쪽을 권합니다. 어종·크기·저항을 글자 배정과 독립적으로 설계하고, 수집 목표도 실제 어종과 개인 기록으로 만들 수 있습니다. 다만 물고기에서 한자를 지우고 출조 전에 문제만 옮기면, 같은 타이밍 게이지를 반복하는 현재의 단조로움은 남습니다. 현재 18종이 공통 몸통·지느러미 구조를 공유하고 힘겨루기 체력도100인 점이 근거입니다.

먼저 의미를 줄 결정은 두 가지입니다.

- **출조 전:** 만나고 싶은 어종 → 포인트 → 맞는 채비를 고릅니다. 빠른 만남과 특정 목표 공략이 다른 선택이 되게 합니다. 배경만 다른 포인트나 항상 최선인 장비는 피합니다.
- **힘겨루기 중:** 물고기가 저항을 예고하면 줄을 늦추고, 힘이 풀리면 누르고 떼어 당깁니다. 하/중/상은 유지하되 물고기 움직임과 중앙 표시가 같은 순간을 가리켜야 합니다. 잘 맞혔을 때 물고기가 실제로 물가에 가까워지는 결과를 보여줍니다. 저항 패턴의 차이를 단순 HP 증가로 대신하지 않습니다.

한자 급수와 손 조작 난이도·낚시 지역은 분리합니다. 6급 학습 때문에 기본 낚시가 자동으로 빨라지거나 미끼가 더 소모되지 않습니다. 도전 속도·줄 파손은 선택 사항이며 편안 조작과 무료 보조는 유지합니다.15절의 즉시 놓기 연타 효율 역전은 새 구조에서도 먼저 해결할 문제입니다.

### 16-2. 추천 흐름과 첫 보상 규칙

`목표 어종 고르기 → 짧은 준비 학습 → 도구 선택 → 연속 낚시 → 도감·포획 정리 → 다음 출조 준비`를 권합니다. 첫 체험은 바로 낚아 볼 수 있습니다. 이후에도 `바로 기본 낚시 / 공부하고 맞춤 미끼 받기`가 함께 보입니다. 낚시 중 입질·챔질과 한자 문제를 동시에 요구하지 않습니다.

- **기본 미끼:** 무료로 계속 이용합니다. 기본 낚시를 반복해도 실제 도감과 포획 기록에 반영하며, 목표종의 기본 조우를 사실상 불가능한 수준으로 낮춰 공부를 강제하지 않습니다.
- **학습 보상:** 처음에는 준비 과제 한 묶음당 원하는 맞춤 미끼3개를 선택합니다. 새 글자1~2자와 예정 복습을 섞은 문항5개 안팎부터 관찰합니다. 쓰기가 포함되면 문항 수보다 실제 활동 시간을 보고 분량을 줄입니다.
- **완료와 정답:** 혼자 정답·도움 후 교정 모두 같은 기본 꾸러미를 받습니다. 설명 뒤 답을 가리고 다시 응답해 보되, 계속 어려우면 다음 복습에 남기고 묶음을 마칩니다. 정답이 나올 때까지 출조를 막거나 처음부터 다시 풀게 하지 않습니다. 도움 버튼만 연속해서 누르는 상태를 실제 응답과 같은 것으로 기록하지 않습니다.
- **맞춤 미끼의 가치:** 단순 판매가격·당기는 힘 증가보다, 원하는 어종을 예측 가능하게 만나는 데 씁니다. 첫 파일럿에서는 적합 포인트의 다음 유효 입질에서 목표종을 보장하는 단순 규칙을 시험합니다. 기본 미끼의 어종도 제한하지 않습니다. 포인트 선택이 단순 확인 절차가 된다면 단서와 선택을 다시 설계합니다.
- **소모:** 첫 실험은 목표 포획 성공 때1개를 확정 소비합니다. 취소·도주 때 예약을 풀어 반환하고 남은 미끼는 보존합니다. 조작 실패를 메우기 위해 다시 공부해야 하는 구조를 피합니다. 현실의 낚시 소모 규칙을 재현한다는 뜻은 아닙니다.
- **첫 버전에서 제외:** 속도·연속 정답·급수 배율·무오답 보너스, 다중 재화, 장비 내구도·유료 수리. 지연 독립 회상의 작은 꾸미기 보너스는 후속 비교 후보이며 처음부터 중첩하지 않습니다.

수량·문항 수·소모 시점은 검증 전입니다. 준비2~3분/낚시3~5분을 관찰 범위로 보고 제한시간은 두지 않습니다. 느리게 배우는 아이의 학습 시간을 포함했을 때도 도구의 가치가 있는지 확인합니다. ‘확률 몇 배’나 낚시 구간의 시간당 수입만으로 보상 가치를 판단하지 않습니다.

### 16-3. 학습을 입장료로 만들지 않으면서 파밍을 줄입니다

공부를 건너뛰는 모든 길을 막는 것과 자유로운 기본 낚시를 동시에 완전히 보장할 수는 없습니다. 이 안은 **학습 후 원하는 공략이 더 잘 이루어져 자발적으로 복귀하는가**를 검증하는 선택입니다. 무료 낚시만 이어지고 한자 회상이 줄면 연결 설계가 실패한 것이며, 경제만으로 시험 공부량을 보장했다고 주장하지 않습니다.

- 보상 대상은 앱이 정한 새 학습·예정 복습의 과제입니다. `learnerId + targetId + ability + reviewOccurrenceId` 등으로 같은 학습 기회에 두 번 보상하지 않습니다. 같은 과제를 재시도·급수 전환·보기 섞기·새로고침해도 중복 보상이 생기지 않습니다.
- 익숙한 글자를 자유롭게 연습할 수는 있지만 그 반복이 무제한 미끼 생성기가 되지는 않습니다. 쉬운 문제 자체를 없애거나 높은 급수에 보상 배율을 주지는 않습니다. 하위 급수 한자가 상위 급수에도 포함된다고 새로운 과제로 위장하지 않습니다.
- 답을 보고 다시 고른 성공은 교정 기록입니다. 독립 정답, 선택·직접 독음/훈음 회상·쓰기, 따라 쓰기·빈칸 쓰기·지연 쓰기를 구분합니다. 보호자 쓰기 채점 대기 때문에 기본 준비 보상을 묶지 않습니다.
- 어획의 판매 코인은 우선 어항·찌·낚싯대 외형에 씁니다. 물고기를 반복 판매하여 학습 보상 미끼를 무한 구매하는 우회로는 첫 경제안에 넣지 않습니다.
- 출조 뒤에만 중요한 회상을 배치하면 그대로 종료할 수 있습니다. 주요 학습·교정은 준비 단계에서 마치고, 다음 날 첫 독립 응답은 보상·힌트·그림 단서 전에 확인합니다.

300자 학습책, 급수별 실제 응답 방식의 자체 연습시험,6-2급부터의 쓰기는 그대로 별도 축입니다. 물고기 도감률·보상·플레이 시간을 한자 숙달이나 합격 준비도로 환산하지 않습니다. 기출 이용 허락과 문항 검수는15-6절처럼 계속 별도로 진행할 수 있으며, 구조 실험이 기출 원문 수집을 기다릴 필요는 없습니다.

### 16-4. 이전 판매 퀴즈안은 첫 후보에서 뺍니다

새 구조에서 물고기는 실제 어종입니다. 물고기 몸에 다시 한자를 붙여 정답을 골라 팔게 하면1:1 연결이 되살아납니다. 출조 전에 공부하고 판매할 때도 문제를 요구하면 두 번의 학습 관문이 됩니다.

첫 손맛 실험에는 상점 자체를 넣지 않습니다. 이후 판매를 붙이면 실제 개체·크기에 맞춰 간단히 판매하고 코인을 받는 흐름을 우선합니다. 이야기형 한자 의뢰는 가끔 선택하는 학습 활동으로 검토하되, 보통 판매와 생계 유지의 필수 관문으로 두지 않습니다.15-5절의 개체 ID·단일 거래·영구 기록 분리 원칙은 여전히 필요하지만 주문의 정답 재고와 한자별 차감 규칙은 새 판매안에서 필요하지 않습니다.

### 16-5. 실제 도감과 수채 게임 그림

**구성:** 낚시에는 수채 배경과 실제 어종의 형태를 살린 그림을 쓰고, 도감 상세에서 `게임 속 모습 / 실제 모습`을 함께 보여줍니다. 생성 그림을 실제 사진으로 표시하지 않습니다. 낚시 중 물고기 몸의 한자·부수 장식은 빼는 후보이며, 한자 장식은 가방·찌·낚싯대 외형으로 옮길 수 있습니다.

- 포획 직후는 어종명·가상 길이·첫 발견/개인 기록·특징 한 줄과 `계속 낚기` 중심입니다. 긴 실제 사진 도감은 선택해서 엽니다.
- 도감 첫 화면은 이름, 구별할 특징 두 가지, 환경 한 문장 정도로 시작합니다. 학명·출처·상세 정보는 펼쳐 봅니다. 패드는 그림과 사진을 나란히, 작은 화면은 위아래로 배치합니다.
- 도감의 실제 서식·형태·관찰된 크기 범위와 게임의 포인트·HP·희귀도·저항 리듬·가상cm 기록을 분리합니다. 게임 희귀도를 실제 개체수나 보전 등급으로 설명하지 않습니다. 사진은 몸 비율을 왜곡하거나 식별 특징을 잘라내지 않습니다.
- 후보 첫3종은 붕어·잉어·메기이며, 그래픽 검토에서는 송사리를 넣는 대안도 나왔습니다. 확정 종목록이 아닙니다. 색 없는 실루엣과 실제 플레이 크기에서 차이가 나는지를 보고 선정합니다. 같은 가상 지역에 둔다고 특정 실제 연못의 생물상을 재현한다고 말하지 않습니다.
- 원화는 정확한 대상 종·성장 상태를 정하고 몸 비율, 입·눈, 지느러미, 꼬리자루, 수염의 수·위치를 대조합니다. 공통 몸통에 색이나 수염만 바꾸는 방식으로 통과시키지 않습니다. 줄과 입의 연결점을 원화·동작·기하가 공유해야 합니다.
- 번짐·붓결·안료 고임·지느러미 투명감으로 수채 품질을 높입니다. 물고기와 UI의 재질·선 굵기를 통일하되 조작 중에는 어종 동작·찌·줄·핵심 타이밍이 먼저 읽혀야 합니다. 미끼 지급은 학습 묶음 경계에서 한 번, 임팩트는 물보라·줄 반동·가까워짐으로 짧게 보여줍니다.

**자료 확인(2026-11-02):** [국립수산과학원 붕어 생물종 정보](https://www.nifs.go.kr/portal/bt/frctA/actionSpeciesSearchView.do?taxonId=9895)에서 국명·학명(Carassius auratus), 종사진 항목, 형태·서식 정보가 있는 것을 확인했습니다. 예를 들어 수염 없는 입, 흐름이 느리거나 수초가 있는 수역의 서식 설명을 조형과 문안 검수에 쓸 수 있습니다. 사진 항목의 원본은 도구에서 스트림 형식으로 열리지 않아 시각 검수하지 못했습니다. 해당 페이지의 추출 내용에서 개별 사진의 공공누리 표시는 확인하지 못했으므로 이 사진의 게임 탑재 허락이 확인됐다는 의미는 아닙니다. 잉어·메기의 개별 도감 원본은 이번에 검수하지 않았습니다.

### 18-2. 정규 진행의 반복 구조

`오늘의 기출 유형 과제 → 답 확인·필요한 교정 → 미끼/채비 선택 → 연속 낚시 → 포획 정리 → 다음 기출 유형 과제`를 한 주기로 만듭니다.

한 묶음에 모든 유형을 억지로 넣지 않고 여러 묶음에 걸쳐 빠짐없이 순환합니다. 예정 복습과 약한 유형을 우선하되 쉬운 유형만 계속 나오지 않게 유형별 미출제 간격을 관리합니다. 정규 모의시험은6급의 유형 비율을 따르고, 일상 연습은 약점과 소개한 범위에 맞춰 조정합니다.

선택형은 입문·교정에 사용할 수 있으나, 모의시험의 입력 방식을 임의로 모두 선택형으로 바꾸지 않습니다. 독음·훈음 직접 입력, 해당 유형의 한자 기입·필순 표현·쓰기 답안 등 실제 응답 방식과의 대응을 문항마다 표시하고 검수합니다. 현재 선택형 변형을 실제 시험과 동등하다고 표시하지 않습니다. 손가락 쓰기에는 보호자 확인을 유지하고, 종이 답안 연습도 별도 확인 대상으로 둡니다.

### 18-4. 반복은 기억 확인과 응용으로 이어져야 함

1. 소개가 필요한 글자·낱말은 먼저 배웁니다. 아직 배우지 않은 내용으로 정답 보상을 막지 않습니다.

3. 교정 뒤 아이가 다시 선택·입력·쓰기 활동을 하게 합니다. 도움 버튼만 누른 상태와 직접 응답을 구분합니다. 계속 어렵다면 교정 기록으로 마치고 과제를 끝낼 수 있습니다.

5. 다음 날 이후의 직접 회상으로 기억을 확인합니다. 오답·도움에는 빠른 재확인, 안정된 독립 성공에는 늘어난 간격을 적용할 수 있도록 계획합니다. 현재처럼 모든 응답을 동일한24시간으로 처리하는 것은 교체 대상입니다.

사용자 요청에 따라 낚싯대의 굵기·곡선·탄성 동작을 개선하고, 더 빠른 게이지에서 중앙을 맞춰 떼는 챔질로 조정했습니다.

- 낚싯대는 손의 고정점에서 시작하는3차 곡선입니다. 손잡이 쪽의 방향은 고정하고 끝으로 갈수록 가늘어집니다. 채비·줄의 장력·누르는 힘에 맞춰 휘어짐을 부드럽게 연결하며, 성공 시 반동 뒤 원래 상태로 돌아옵니다.
- 선단과 찌의 윗고리, 찌의 아랫고리와 물고기의 입은 같은 좌표를 사용합니다. 모바일에서도 낚싯대 끝이 찌의 윗고리보다 위에 있도록 높이를 보정합니다. 물고기가 다가와도 낚싯대 길이가 함께 짧아지지 않게 기준 포인트를 유지합니다.
- 게이지 한 번 이동: 편안 모드2,800→1,700ms, 도전 모드2,200→1,350ms입니다. 학습 급수와 조작 난이도는 분리합니다.
- 상44.5~55.5%, 중38~62%, 하30~70%이며 안쪽 판정을 우선합니다. 기본 피해는 상50/중28/하12, 바깥 구간과 시간 초과는 빗나감0입니다. 몸부림칠 때 기존60% 피해 계수를 적용합니다.
- 표시 영역과 판정은 같은 엔진 설정을 사용합니다. 놓은 위치는 짧은 결과 시간 동안 유지하고 중앙 성공에 금빛 강조를 줍니다. 빠른 연타가 성공보다 먼저 다음 차례를 얻지는 않습니다.
- 편안 모드의 줄 보호와 자동 도움은 유지합니다. 도전 모드는 장력을 관리해야 하며 실패가 누적되면 놓칠 수 있습니다. 학습 점수·문항·시험 데이터는 이 변경과 무관합니다.

검증: 전체 한자·버전 검사71개 통과, 마지막 모바일 높이 보정 후 관련20개 검사 통과. 실제 UI에서 빠른 놓기/시간 초과의 체력 유지, 중앙 성공의 체력 감소,375px 화면 가로 넘침 없음과 물고기/조작부 분리를 확인했습니다. 공개 배포는 수행하지 않았습니다.
