# 공식 배정한자 데이터 — 8급부터 6급까지

수집·변환일: 2026-10-26. 공식 출처: [사단법인 한국어문회 급수배정](https://www.hanja.re.kr/kccpt/exam/levelConfirm.do).

## 저장된 것

- `catalog.json`: 중복 없는 300자. 한자, 대표 훈음, 모든 대체 훈음, 공식 신습 급수, 부수, 총획수, 부수 외 획수, 원본 음표, 원본 엑셀 행 위치를 담습니다.
- `stages/`: 게임의 9급 입문·8급·7-2급·7-1급·6-2급·6-1급 매핑 6개. 한자 ID로 본표를 참조합니다.
- `characters.csv`: 사람이 열어 확인하기 쉬운 300자 목록. 대체 훈음은 `sourceHunEum`에 원문 그대로 남습니다.
- `validation-report.json`: 공식 HWP/엑셀 대조 결과, 급수별 수량, 쓰기 범위와 문자 정규화 기록.
- 원본: `../../docs/sources/hanja-official/2026-10-26/`. 공식 HWP 5개, 전체 엑셀, 급수 안내 HTML 스냅샷, 추출 본문, 엑셀에서 선택한 원문 행, 다운로드 출처·SHA-256을 담은 `manifest.json`이 있습니다. 안내 HTML의 일회용 세션 토큰은 제거했습니다.

## 범위와 사용 방법

게임 진행 순서의 새 글자 수는 20 / 30 / 50 / 50 / 75 / 75입니다. 공식 누적 읽기 범위는 입문 20자, 8급 50자, 7급Ⅱ 100자, 7급 150자, 6급Ⅱ 225자, 6급 300자입니다. 공식 8급 신습 50자와 게임의 입문 이후 새 글자 30자는 다른 수치입니다.

- `newCharacterIds`: 입문부터 순서대로 플레이할 때 해당 단계에서 추가되는 글자입니다. 여섯 단계 전체에서 300자를 한 번씩 나눕니다.
- `officialNewCharacterIds`: 공식 급수의 신습 글자입니다. 8급은 50자이며 입문에는 공식 신습 급수가 없습니다.
- `readingCharacterIds`: 해당 단계까지의 전체 읽기 범위입니다. 높은 단계로 직접 들어가도 이 목록과 실제 학습 기록을 이용해 새 글자·복습 글자를 결정합니다. 이전 단계를 배웠다고 가정하지 않습니다.
- `writingCharacterIds`: 공식 HWP의 쓰기 목록을 실제 추출했습니다. 6-2급은 8급 읽기와 같은 50자, 6-1급은 7급 읽기와 같은 150자입니다.
- `officialGrade`: `8`, `7II`, `7`, `6II`, `6`. 게임 표시명과 다릅니다. 입문은 null입니다.
- `scopeStatus`는 원본 목록 대조 상태입니다. 콘텐츠 준비와 게임 구현은 다릅니다. 현재 수채 시안에서는 6개 단계의 전체 읽기 범위를 낚시에 연결했습니다. 6-2·6-1급은 윤곽 쓰기 연습과 보호자 채점을 제공합니다. 획순·필기 인식 자동 채점 및 단계별 별도 풍경은 미구현입니다.

`catalog.characters`를 id로 색인한 뒤 원하는 stage의 `readingCharacterIds`를 조회하면 됩니다. 학습 기록도 급수가 아니라 공통 한자 ID에 연결합니다. 기존 숫자 시안의 숫자 ID와 이 데이터의 Unicode 기반 ID는 다르므로 저장 이관 처리가 필요합니다. 현재 수채 플레이 코드는 이 본표를 읽습니다. 이전 두 숫자 시안 저장 키의 기록은 Unicode ID로 이관하며, 같은 한자의 기록은 더 큰 횟수를 유지하고 중복 합산하지 않습니다.

## 원문을 보존한 부분

- 호환 한자 `車/金/樂/不`는 게임 키를 `車/金/樂/不`로 NFC 정규화했습니다. 원문은 `sourceCh`에 남습니다. 서로 다른 한자를 임의로 합치거나 `敎`를 `教`, `靑`을 `青`로 바꾸지는 않았습니다.
- `readings`에는 `車: 거·차`, `樂: 락·악·요`, `北: 북·배` 등의 훈음이 모두 있습니다. 첫 훈음을 대표값 `hun/eum`에 둡니다.
- `:`, `(:)`, 괄호 주석은 발음용 `eum`과 분리하고 `sourceEum/notation/sourceHunEum`에 보존했습니다. 슬래시로 나열한 훈도 원문대로 유지했습니다.
- `totalStrokes`는 원본의 **총획**, `radicalExtraStrokes`는 원본의 **획수** 열입니다. 두 수치를 혼동하지 않습니다.
- 공식 원본의 六 대표훈음은 **여섯 륙**입니다. 기존 10자 프로토타입의 `여섯 육`과 차이가 있어 추후 데이터 연결 시 정리해야 합니다. 수채 시안에서는 새 본표를 연결하여 공식값 륙을 사용합니다.

## 검증 범위와 남은 콘텐츠

공식 HWP의 본문 전체를 추출했고(길이가 제한되는 PrvText 미리보기는 기준으로 쓰지 않음), 급수별 읽기·쓰기 목록과 엑셀 급수 코드의 집합을 대조했습니다. 5개 읽기 집합과 2개 쓰기 집합이 정확히 일치합니다. 300자의 문자·훈음·부수·획수는 공식 표에서 가져왔지만 별도 사전 대조나 글꼴 렌더링·한국식 필순·음성 청취 검수는 수행하지 않았습니다. 낱말 예시·그림·획 경로·음성은 이 자료에 포함되지 않습니다.

원본 자료를 내려받았다는 사실은 원본 파일 재배포·상업 이용의 별도 허가를 확인했다는 뜻은 아닙니다. 원본은 출처 추적용으로 보관했으며 배포·커밋·공개 업로드하지 않았습니다.

## 다시 생성하기

원본만으로 오프라인 재변환할 수 있습니다.

```sh
python3 -m pip install --target /tmp/hanja-import-libs -r tools/requirements-hanja-import.txt
PYTHONPATH=/tmp/hanja-import-libs python3 tools/import_hanja_catalog.py
node --test tests/hanja-catalog.test.cjs tests/hanja.test.cjs
```

원본 새로 받기: `python3 tools/fetch_hanja_sources.py --snapshot YYYY-MM-DD`. 기존 날짜의 원본은 덮어쓰지 않고 거부하며, 모든 다운로드가 검증된 뒤 새 스냅샷을 확정합니다. 새 스냅샷으로 변환할 때는 `python3 tools/import_hanja_catalog.py --snapshot YYYY-MM-DD`를 사용합니다. 공개 다운로드 양식의 세션·CSRF 처리를 따르며 자격 증명은 사용하지 않습니다. HTML 오류 응답을 HWP·XLS로 저장하지 않도록 바이너리 형식을 확인합니다. 수집일 폴더는 스냅샷이므로 향후 갱신은 새 날짜 폴더를 사용하는 방식으로 관리합니다.
